# API v1 implementation contract

Base: `https://finance.example.com/api/v1`. JSON requests/responses, except 204 responses and signed Clerk webhook payload. Types and strict request validators live in `@finance-tools/contracts`. Times are UTC ISO-8601 strings. Path IDs use `idSchema`; namespace is `settings|history`. Unknown request fields are rejected. Shared `MAX_REQUEST_BODY_BYTES` is 1,572,864 (1.5 MiB), allowing base64 expansion of up to 1 MiB ciphertext (`MAX_DOCUMENT_BYTES`). The ciphertext schema permits at most 1,398,102 unpadded base64url characters; server also checks decoded byte size and canonical encoding. Never accept account IDs from the client: derive from authenticated session.

All failures: `{error:{code,message,requestId,currentRevision?}}`. Statuses: 400 invalid input, 401 invalid/expired credentials, 403 scope/origin denial, 404 missing resource, 409 revision conflict/reused mutation with different payload, 410 expired pairing/history, 413 too large, 429 rate limited, 500 internal. Do not expose secrets or crypto errors. Responses containing credentials/private data use `Cache-Control: no-store`.

## Authentication and sessions

`/me` includes the authenticated account's authoritative `clerkSubject`. Browser restoration compares this server mapping with any currently signed-in Clerk actor before key restoration/release or data display; missing local identity bindings are never proof of a matching identity. Clerk absence/expiry still permits app-session restoration. A late conflicting signed-in actor immediately fences keys/views and requires explicit reconnect.

Own access JWT lasts 900 seconds, with issuer, audience, subject account ID, session ID, scopes, iat, exp, jti. Validate signature/issuer/audience and active persisted session on every call. Opaque refresh tokens have >=256 bits entropy; store hashes except short-lived encrypted successor retry state. Rotate atomically on refresh. Each logical refresh persists one `X-Finance-Refresh-Id` UUID and its input credential until completion. Exact predecessor/UUID retries within 120 seconds recover the same successor; a competing UUID in grace returns 409, and predecessor replay after grace revokes the family. Retry state uses independent `SESSION_WRAP_SECRET`. Clients serialize refreshes and reuse the UUID after network failure. Idle expiry is **30 days**, fixed absolute expiry **90 days from creation**; refresh/cookie idle deadlines are capped to the absolute deadline. Additive migration caps existing sessions using original millisecond timestamps. Persisted client kind/scopes cannot escalate during refresh.

Browser refresh token: `__Host-finance-refresh`, Secure, HttpOnly, SameSite=Strict, Path=/, no Domain; never return it in JSON. Browser access token lives in memory. Cookie mutation calls require exact configured Origin (reject missing/null) and `X-Finance-CSRF: 1`; CORS allows only app origin with credentials. Userscript refresh credentials are explicit JSON and stored in GM storage, not cookies. Script uses Bearer access token and no credentials/cookies. No wildcard credentialed CORS. Do not trust client.kind alone to bypass cookie CSRF checks.

| Method/path                | Auth                                    | Body                                  | Success                                                               |
| -------------------------- | --------------------------------------- | ------------------------------------- | --------------------------------------------------------------------- |
| POST `/session/exchange`   | fresh Clerk token in body               | `exchangeRequestSchema`               | 200 `SessionTokens`; browser cookie set, script refreshToken returned |
| POST `/session/refresh`    | refresh cookie or explicit script token | `refreshRequestSchema` (`{}` browser) | 200 `SessionTokens`; rotate refresh                                   |
| POST `/session/logout`     | refresh credential (or own access JWT)  | `refreshRequestSchema`                | 204 revoke current session and clear cookie; idempotent               |
| POST `/session/logout-all` | own access JWT                          | `{}`                                  | 204 revoke all account sessions, clear cookie                         |

Clerk token verification uses configured issuer/JWKS/audience and authorized parties; exchange requires token issued within last 5 minutes. Provision account by Clerk subject. Free entitlements are server-owned defaults, never writable by client.

Own sessions are independent of the continuing Clerk browser login. Reload first attempts cookie restore; a valid app session works with Clerk signed out. A fresh signed-in identity automatically exchanges once after an expected anonymous 401, but transient restore/exchange failures and explicit logout never silently mint a retry loop. An actual prior identity conflict requires explicit connection and fences old views. Clerk is needed for exchange and sensitive step-up, not ordinary refresh. Private remembered keys do not extend 30-idle/90-absolute-day limits. Explicit logout clears app keys/state and signs out Clerk. Revoke-all advances the persisted account epoch atomically; concurrent old-epoch issuance cannot survive it. Session listing includes current-device status, idle and absolute expiry.

Products are `portfolio|bank-subcaps`, separate from namespaces. `client.products` is mandatory and persisted with the session. Browser requests both products; each userscript requests only its respective product. `client.name` is a non-authoritative display label, never a permission source. Server checks product scope on every document operation and filters list/export results by persisted product scopes; document IDs/prefixes are not permission boundaries. PUT requires a `product` field, persisted alongside the encrypted document in D1 and returned in `StoredDocument`; updates cannot change an existing document's product. Cursor validity also binds product scopes. `/me` returns the session's products and namespaces.

## Pairing

| Method/path             | Auth                          | Body                                           | Success                                                               |
| ----------------------- | ----------------------------- | ---------------------------------------------- | --------------------------------------------------------------------- |
| POST `/pairing/create`  | unauthenticated, rate limited | `pairingCreateRequestSchema` (userscript only) | 201 `PairingResponse`                                                 |
| POST `/pairing/inspect` | own browser access JWT        | `pairingInspectRequestSchema` (ID and code)    | 200 `{client}` containing exact stored label/product/namespace scopes |
| POST `/pairing/approve` | own browser access JWT        | `pairingApproveRequestSchema`                  | 204 bind pairing to approving account and exact requested scopes      |
| POST `/pairing/redeem`  | possession of secret          | `pairingRedeemRequestSchema`                   | 200 `SessionTokens` including script refreshToken                     |

Pairings expire after 10 minutes. Cryptographic random ID/256-bit secret/8-digit code; hash secret/code in storage. UI shows client name and scopes before approval. Approve only once; redeem atomically once, only after approval; 409 pending/already approved, 410 expired/consumed. Limit guesses per pairing and IP. Never pair by short code alone. Pairing does not transfer a vault key/passphrase/recovery secret.

After pairing, Standard scripts automatically acquire the Standard data key through `/vault/key`; Private scripts separately import a supported key file or unlock with passphrase/recovery. Ordinary script refresh does not require Clerk.

## Vault and encrypted documents

| Method/path                        | Auth                                       | Body/query                                    | Success                                                                 |
| ---------------------------------- | ------------------------------------------ | --------------------------------------------- | ----------------------------------------------------------------------- |
| GET `/vault`                       | access JWT                                 | none                                          | 200 `VaultResponse`, 404 uninitialized                                  |
| PUT `/vault`                       | browser access JWT                         | `vaultPutRequestSchema`                       | 200 `VaultResponse`; revision 0 means create-only                       |
| POST `/vault/key`                  | active browser or paired script JWT        | `{expectedRevision}`                          | Standard only: `{revision,keyVersion,rawKey}`; no-store, revision-bound |
| PUT `/vault/mode`                  | browser JWT + fresh matching Clerk factors | `vaultModeRequestSchema`                      | 200 `VaultResponse`; atomic mode/revision CAS, metadata-only receipt    |
| GET `/documents/:namespace`        | access JWT with namespace scope            | `?cursor=<opaque>&limit=1..100` (default 100) | 200 `DocumentListResponse`                                              |
| GET `/documents/:namespace/:id`    | namespace scope                            | none                                          | 200 `StoredDocument`                                                    |
| PUT `/documents/:namespace/:id`    | namespace scope                            | `documentPutRequestSchema`                    | 200 `StoredDocument`                                                    |
| DELETE `/documents/:namespace/:id` | namespace scope                            | `documentDeleteRequestSchema`                 | 204                                                                     |
| GET `/export`                      | browser access JWT                         | `?cursor=<opaque>`                            | 200 `ExportPage` (encrypted only)                                       |
| DELETE `/account`                  | browser access JWT + fresh Clerk           | `accountDeleteRequestSchema`                  | 204                                                                     |

CAS: expectedRevision must equal stored revision; absent document has revision 0. Each successful write increments revision; delete preserves revision tombstones. Account/namespace/document/mutationId bind permanent payload-bound deduplication records; identical replay returns original status/body, different replay returns 409. Finite receipt/metadata budgets reject new writes rather than discard replay safety. Validate vault wrapper key versions against keyVersion; ordinary rewrap cannot increment an established keyVersion. Document AAD binds account, namespace, document ID, schemaVersion and keyVersion. The document write path enforces structure/current keyVersion but does not decrypt or authenticate tags/content; Standard's server-recoverable key does not imply server validation of financial plaintext.

New null vaults initialize Standard atomically at verified exchange, including webhook-preprovisioned accounts. Conditional initialization releases only the committed winner's key; every non-null legacy vault stays Private. Public vault metadata accepts legacy version 1 or strict version-2 `mode: standard|private` variants. Standard contains only version/mode/keyVersion. Server wraps remain in separate D1 metadata, encrypted with independent `VAULT_WRAP_SECRET`; absent/malformed configuration fails with `vault_wrap_not_configured`. `/vault/key` rechecks persisted account/session eligibility and exact mode/revision after unwrap, before returning key material.

Mode requests contain a UUID, expectedRevision, fresh Clerk token, and new version-2 metadata. Private→Standard also supplies transient `rawKey` and `trustServer:true`; Standard→Private supplies only client wrappers, never raw key. Both retain keyVersion. Browser locally authenticates the existing wrapper or tests the new recovery wrapper; server prevents cross-account access but cannot certify a malicious owner's client-generated private wrapper continuity. Mode requests must bypass persisted generic mutation queues. Exact replay is payload-bound (excluding replaceable Clerk proof); receipts contain only revision/mode/keyVersion, never raw keys or server wraps. Standard→Private clears the active server wrap, not prior backups/cached keys. Old `/vault` writes remain Private-only and cannot replace a Standard vault.

Default free limits: 10,000 documents, 1 MiB decoded ciphertext per envelope, 64 MiB aggregate stored envelope JSON bytes, 50,000 mutation receipts and 16 MiB metadata. Server enforces quotas atomically, including retained payload versions and tombstones; product/namespace declarations never bypass account-wide limits. Payloads reside only in D1, once per required immutable version. Payload insertion, CAS pointer update and mutation receipt are one atomic SQL command-trigger operation; failures leave no partial writes and concurrent identical retries allocate no additional payload. No upload reservations or expiry recovery states are needed. Cleanup directly deletes unreferenced payloads in bounded SQL batches that atomically check both document and receipt references. The Workers Free 500 MB database is shared by all accounts and includes retained versions, metadata and indexes; logical account quotas do not reserve physical capacity.

History PUT requires occurredAt; settings PUT forbids it. Retention is a rolling **three calendar month** UTC cutoff, subtracting months with day clamped to target month's last day; not 90 days. Reject older history writes with 410; exclude expired history from reads/export and physically purge scheduled. Keep settings indefinitely until deletion, including original versions needed for permanent mutation replay. List sorts IDs ascending with opaque account/namespace/product-bound cursor; returns at most limit current nonexpired documents within a 2 MiB envelope JSON plus metadata allowance budget. No decrypted values are ever sent to server. Missing/corrupt encrypted payloads return 500 `storage_unavailable`, not partial successful backups.

Account delete token must belong to same Clerk subject and be issued within 5 minutes. Server also verifies signed Clerk `fva` factor ages: first factor age plus elapsed token age must be <=5 minutes. If trusted Clerk user state indicates an enrolled second factor, require that factor fresh too; reject missing/malformed/unverified claims. A recently issued JWT alone is not recent authentication. Immediately revoke access and leave an account tombstone, then idempotently remove D1 records/payloads in bounded scheduled batches. Deletion must prevent a concurrent write/provision from resurrecting account. Do not delete Clerk identity implicitly.

`/export` returns strict `ExportPage`: `{version:1,accountId,exportedAt,vault,documents,cursor}`. Follow the opaque signed cursor in separate requests until null. Each request authenticates an active browser session; the cursor binds the account, export endpoint and persisted product/namespace grants. Pages seek by namespace/ID and contain at most 100 documents with a 2 MiB envelope JSON plus metadata allowance budget; payloads are fetched in one ownership-scoped bulk D1 read, not N+1 queries. FinanceClient assembles the unchanged version-1 `ExportResponse` full backup locally (no cursor), retaining the first page's vault/export time. Export is not a snapshot: edits, vault rewraps, expiry or deletions between requests may change results. A failed page rejects the full export rather than returning a partial backup.

The server's Standard metadata is **not a portable key backup**. `FinanceClient.encryptedExport(passphrase)` requires an explicit 12+-character export-only passphrase for Standard and substitutes a portable Private wrapper locally, never raw/server-wrapped keys. Private backups retain legacy/v2 wrappers and credentials. Restore rejects bare Standard metadata exports, authenticates all ciphertext before writes, and supports an empty auto-initialized Standard destination by reencryption under its existing key. Nonempty destinations require the exact interrupted backup and matching restored content; no unrelated documents are overwritten. Supported key files are strict `{format:'finance-tools-key',version:2,accountId,keyVersion,recoverySecret}`; legacy version-1 account/recovery-secret files remain accepted for Private unlock.

Export is encrypted only and does not constitute decrypted recovery. Local plaintext export/recovery disclosure requires explicit user action and local unlock/reverification UI; do not silently export unlocked data. Hourly Cron performs retention/deferred cleanup in fewer than 50 D1 statements and small physical payload-delete batches. The configuration targets Workers Free without R2 or a Paid-only override; production CPU/daily quotas have not been measured or certified by local tests.
