# Portfolio domain

Typed money, holdings, account snapshots, card captures, provenance and Singapore posting-calendar utilities. Money uses safe integer cents; unsupported precision and unknown currency return null, not zero. No FX conversion or averaging of holding returns is performed. `identity(...parts)` asynchronously SHA-256 hashes scoped identity components; hashes are pseudonymous, not encryption, and low-entropy account identifiers require protected storage.

`threeMonthCutoff(capturedAt)` subtracts three calendar months from the UTC date, clamping month-end (May 31 → February 28/29), matching API history retention. `retainThreeMonths` compares strict posting-calendar dates to that inclusive cutoff and to the current Singapore date for future exclusion. Singapore posting dates remain separate from UTC retention computation.

`bindCardCapture(capture, explicitAccountDiscriminator): Promise<CardCapture>` binds a user-supplied stable account discriminator using provider/product-scoped SHA-256 identities. It returns a copy with `persistence: 'account-bound'`, replacing account, snapshot and transaction IDs without retaining the discriminator. Repeat binding to the same discriminator is stable; different accounts cannot collide by sharing a reference. Adapter `identityKey` preserves transaction identity across rebinding/corrections. Older captures without that key fall back to their existing transaction ID. Unidentified captures are `persistence: 'ephemeral'` with `EPHEMERAL_ONLY`; do not store them.

`aggregateCardHistory(captures, capturedAt?): CardHistory[]` requires bound captures, groups by provider/product/account, deduplicates provider-reference transaction IDs and selects the chronologically latest correction. Changed rows are surfaced in `changes` and provenance flags. Currency-specific totals never double count overlaps. Maybank `snapshot-local` identities cannot establish cross-capture overlap or disjointness: only the latest loaded observation is totaled, with `totalsConfidence: 'latest-capture-lower-bound'`, ambiguous IDs/months and warnings. This lower bound refers to observed debit history, **not** exact net spending: Maybank credits remain omitted. Coverage is always unknown and complete is false. Use the optional current instant to prune history on every read/save, not merely its last observation timestamp.

## Runtime payload validation

Zod exports include `moneySchema`, `provenanceSchema`, `portfolioSnapshotSchema`, `cardCaptureSchema`, `cardSettingsSchema`, `allocationSettingsSchema`, `productSettingsSchema` and `normalizedProductPayloadSchema`. The corresponding `parsePortfolioSnapshot`, `parseCardCapture`, `parseCardSettings`, `parseAllocationSettings`, `parseProductSettings` and `parseNormalizedProductPayload` functions throw on invalid data. Clients, web and runtime must parse decrypted/imported data **before any import, save or render**; TypeScript annotations alone are not validation. Objects are strict, providers/products are enums, timestamps reject impossible dates and observations more than five minutes in the future, money is safe integer minor units, flags are strings, and map records reject null, arrays and dangerous own keys. Legitimate own merchant `toString` is supported; inherited rules are not.

## Allocation comparison

`calculateAllocations(snapshots, settings): AllocationResult[]` validates inputs and uses the latest snapshot per provider/account. Each `AllocationScope` defines account, optional goal, bucket, optional `holdingIds` membership, currency, asset/liability section and CPF/SRS/cash/unknown account type. No currency conversion or debt netting occurs. Scope targets are own-property holding-ID maps with integer `targetBps` (0–10000), same-currency `targetAmount`, `fixed`, or `excluded`; percentage targets must not exceed 10000 bps. Optional same-currency asset-only projected deposits affect target balances, not current actual percentages. Amount calculations truncate fractional cents; basis points truncate fractional bps.

Outputs include actual/projected totals, actual/target basis points, target amount, target-minus-actual `deltaMinor`, and actual-minus-target `driftBps`. Fixed holdings retain their current target amount; excluded holdings are omitted from the denominator. Unknown valuations suppress percentage denominators/percentage-derived targets and emit warnings, not zeros presented as known values. Unsupported source account types remain unknown and flagged. Scope views can overlap; do not sum overlapping buckets. This is balance allocation, **not aggregated or recomputed TWR**.

## Encrypted bank retention

`partitionCardCaptureByPostingDate(capture): Promise<PostingDatePartition[]>` emits one bound capture per posting date and an `occurredAt` of that posting date at **00:00 UTC**. Use this field for the encrypted record's retention timestamp; never use provenance `capturedAt`, which remains the observation time. Stable `observationId` lets aggregation reassemble daily shards before applying conservative Maybank latest-observation logic. The server can expire daily encrypted documents without reading rows. Re-prune rows locally using the current cutoff on read/import/save; the oldest retained day is inclusive. Historical re-observation must not refresh transaction retention. Dropped encrypted shards cannot establish complete coverage.
