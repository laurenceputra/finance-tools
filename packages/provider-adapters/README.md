# Provider adapters

`normalizeEndowus({performance, investible, goals}, capturedAt)`, `normalizeFsm(payload, capturedAt)`, `normalizeOcbc(payload, capturedAt)` return `Promise<PortfolioSnapshot[]>`. `captureUob(document, capturedAt)` and `captureMaybank(document, capturedAt)` return `Promise<CardCapture[]>`. Types are re-exported. No HeyMax, networking, persistence or legacy UOB adapter is included.

Endowus unions all goal IDs and adds known pending amounts to valuation; investible total is not principal. Missing returns stay null. FSM scopes identities by refno/code/subcode and omits DPMS headers. Cost basis is valuation minus known same-currency profit; percentages are never averaged. Endowus/FSM SGD local defaults reflect the Singapore source, not FX conversion. OCBC preserves asset/liability scope and refuses unknown original/reference currency rather than fabricating SGD.

DOM captures require one visible supported heading owning a uniquely qualified table. Missing/ambiguous context returns no capture. Explicit `data-account-id`/`data-card-id` supplies account scope; otherwise captures are explicitly `persistence: 'ephemeral'`, flagged `ACCOUNT_CONTEXT_UNAVAILABLE` and `EPHEMERAL_ONLY`. They must not be persisted until `bindCardCapture(capture, explicitAccountDiscriminator)` (re-exported here) supplies a stable user-selected account identity. Binding hashes provider/product/account, replaces snapshot/account/transaction IDs and never retains the plaintext discriminator. Rebinding is stable.

UOB five-cell/two-date-span rows use fixture-inferred sign inversion and exclude payments. UOB transaction identity uses reference plus occurrence, not mutable amount/merchant/date, allowing corrections to deduplicate. Maybank intentionally retains debit-only legacy behavior and flags omitted credits. Duplicate occurrences remain distinct; Maybank synthetic keys include date/merchant/amount and cannot detect corrections to those fields. `aggregateCardHistory` is re-exported for bound account history deduplication and correction reporting. History retention uses rolling three UTC calendar months, clamped at month-end; posting dates remain Singapore calendar dates. Source-loaded coverage is always unknown/incomplete. SHA-256 IDs are pseudonymous, not encryption.

UOB transactions expose `identityConfidence: 'provider-reference'`; Maybank synthetic transactions expose `'snapshot-local'`. Maybank can use an explicit observed row `data-ref-no`/`data-reference` attribute (bounded alphanumeric/hyphen reference) as a provider reference; no reference is invented. Without those fields, cross-observation totals use only the latest loaded observation and surface ambiguous IDs/months; remaining caps must be suppressed. `partitionCardCaptureByPostingDate` is re-exported for posting-day encrypted record retention, with observation time preserved separately. Provider account types are currently unknown and flagged, not inferred to be cash/CPF/SRS. Consumers must use the portfolio-domain runtime schemas before import/save/render.
