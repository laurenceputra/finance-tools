# Finance Tools

TypeScript pnpm workspace for a React/Vite dashboard, Hono Cloudflare Worker and esbuild userscripts. See application packages for implemented flows; this README is not a claim of production deployment or live-provider verification.

Use Node 22 and `corepack pnpm install --frozen-lockfile`, then `corepack pnpm check`. Individual commands: `test`, `typecheck`, `build`, `dev`, `types:worker`, `deploy:cloudflare`. Workspace imports use `@finance-tools/contracts` and `@finance-tools/crypto` exports (source TypeScript; bundlers resolve them). No global package-manager activation needed.

Root build explicitly runs `@finance-tools/web` before `@finance-tools/userscripts`: Vite clears root `dist`, then esbuild appends `dist/scripts/*.user.js`. Never parallelize these builds. API package `@finance-tools/api` is typechecked by root typecheck and bundled by Wrangler at deployment, never published as an asset. Generate bindings with `corepack pnpm types:worker`; consume generated Env rather than handwritten binding interfaces. Generation emits Env only; the pinned `@cloudflare/workers-types` package supplies runtime declarations, avoiding a large copied runtime definition file.

`corepack pnpm dev` starts local-only Wrangler on 8787 and Vite on 5173; web must proxy `/api` to `http://localhost:8787`. Copy `.dev.vars.example` to ignored `.dev.vars`, provide development Clerk keys and independent random secrets, and apply local migrations with `corepack pnpm exec wrangler d1 migrations apply finance-tools --local`. Local login requires Clerk authorized party/origin configuration matching `http://localhost:5173`. Run `corepack pnpm build` once before dev if Wrangler needs the asset directory.

See [API contract](docs/API.md) and [security boundaries](docs/SECURITY.md).

## Hosting

One Worker serves API plus `dist` static assets at **finance.example.com**. Wrangler disables workers.dev and preview URLs. Compatibility date is 2026-10-04. Hourly Cron (`0 * * * *`, UTC) handles bounded retention/deferred deletion. All encrypted payload storage is **D1-only**, targeting **Workers Free** without R2 or a Paid subrequest override. Export uses count/byte-bounded, separately authorized signed-cursor pages; the browser assembles the existing version-1 backup. Local checks do not certify the Free 10 ms CPU or daily D1 quotas. The 500 MB shared database includes every account, retained versions, metadata and indexes; per-account logical quotas do not reserve capacity. Export is not an atomic snapshot.

### One-time operator setup

1. D1 `finance-tools` and the deployed Worker already exist; do not create duplicates. Tracked `wrangler.jsonc` is a placeholder template. Set private Builds variables `CLOUDFLARE_D1_DATABASE_ID` (existing database UUID) and `APP_HOSTNAME` (bare production hostname; `finance.example.com` is only an example). Account selection/authentication comes from native Builds context. No R2 setup or billing upgrade is required. See [production setup checklist](docs/SETUP.md) for exact steps and remaining verification.
2. Configure a production Clerk instance with domain/origin `https://finance.example.com`, the audience `finance-tools`, and required factor-verification claims. Configure lifecycle webhook to `/api/v1/webhooks/clerk` and subscribe to both `user.deleted` and `user.updated` for deletion and ban/unban handling.
3. Set Worker runtime secrets through the Cloudflare dashboard: `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `CLERK_ISSUER`, `CLERK_AUDIENCE`, `CLERK_WEBHOOK_SECRET`, `ACCESS_JWT_SECRET`, `SESSION_WRAP_SECRET`, **`VAULT_WRAP_SECRET`**; optional `CLERK_JWT_KEY`. Generate independent random 32-byte base64url JWT/wrapping secrets. Standard initialization/key release fails closed without the dedicated vault secret. Losing it loses Standard recovery; do not replace it without a separately planned wrap migration. Keep actual secrets out of Git, build variables, logs and client bundles. If web needs a build-time publishable key, set only its documented public Vite variable in Builds.
4. Configure **Cloudflare Workers Builds**, root directory `/` (repository root), production branch `main`. Build command: `corepack pnpm install --frozen-lockfile && corepack pnpm check`. Deploy command: `corepack pnpm deploy:cloudflare`. Preflight requires main Builds, validates both private variables and atomically generates ignored root `wrangler.deploy.jsonc` with restrictive permissions. **Remote D1 migrations first**, then deployment use this same generated config; it is cleaned up afterward, including failure. Assets remain limited to `dist`. Builds manages authentication through its native **API token** setting; do not define custom `CLOUDFLARE_API_TOKEN` or `CLOUDFLARE_ACCOUNT_ID`. The selected token must have **Account → D1 → Edit** for migrations, which the default Builds token permissions do not include. Adjust that token under **My Profile → API Tokens**, or select an appropriately scoped token in the Builds **API token** setting. See [official configuration](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/). Use backward-compatible migrations: migration success followed by deployment failure must leave the old Worker operational.
5. Disable nonproduction branch builds and preview deployments in the Builds dashboard. Confirm only main auto-deploys, custom domain resolves to this Worker, no workers.dev/preview URLs exist, and Cron is registered. Deployment preflight additionally requires Cloudflare's `WORKERS_CI=1` and `WORKERS_CI_BRANCH=main`; missing/other values are rejected before remote migrations. These flags are a safety check, not a security boundary. Do not substitute Pages branch variables or set these flags to bypass the guard for manual deployment. Dashboard branch configuration remains mandatory.

The initial schema was consolidated before first deployment; future production schema changes require new backward-compatible migrations. An existing **disposable** local development database using an earlier schema needs recreation before local migrations are applied; migrations do not upgrade it in place. No database has been reset as part of this change. Preserve any local user data; do not recreate a database containing data you need without a separately authorized preservation plan.

GitHub Actions validates formatting and checks with frozen pnpm lockfile and read-only contents access; no production credentials or GitHub deployments. Never enable Pages deployment. **The Worker has been deployed, but production Clerk configuration, secrets and end-to-end application readiness are not certified.** Passing local checks is not production readiness or measured Workers Free compatibility certification.

The deployment orchestrator invokes the pinned local Wrangler through Node without a shell, inherits normal Wrangler output without dumping the environment, forwards interruption signals, and stops immediately if preflight or migrations fail. Preflight validates JSONC, the DB UUID and disabled previews without generating a separate deployment config.

### Feature boundaries

- Portfolio/bank-subcap adapters are separate products with scoped userscript access; provider layouts/data must be verified against actual authorized sessions before relying on results. Fixture coverage is not live verification or financial advice.
- Fresh verified Clerk sign-in automatically connects the browser and opens a new **Standard** vault. Standard keys are server-recoverable, not end-to-end private from the operator. Optional **Private** mode uses a saved account/version-bound key file or passphrase/recovery secret; existing legacy vaults remain Private. Private keys cannot be recovered by the service.
- Browser restoration first uses the application's refresh cookie, independently of Clerk's current login state. App sessions expire after 30 idle days or 90 absolute days; migration caps existing sessions from their original timestamps. Explicit logout revokes app access and signs out Clerk; Clerk expiry alone does not disconnect Finance. Fresh factor verification is required for deletion and encryption-mode changes.
- Capture adapters can read only the supported data actually available in the authorized provider page/context. Paginated, unloaded, virtualized or changed layouts may yield partial/unsupported capture; do not describe fixtures or a successful script build as complete live-provider support. A capture timestamp records observation, not necessarily the provider's source-data timestamp.
- Settings persist; history expires after three calendar months. Export is encrypted and recovery-safe only when the corresponding unlock credential is preserved.
- Private local indefinite unlock is opt-in and cannot guarantee OS-backed protection. Standard keys stay in memory by default. Mode changes keep the same data key/version and clear remembered keys/views; switching to Private does not erase old backups, receipts or cached keys. Data-key rotation is not implemented.
